# 研究報告格式規範

自 2026-08-24 起，研究進度報告預設使用 HTML，不再預設產生 PowerPoint。

## 必要格式

- 報告輸出放在 `outputs/reports/`，副檔名使用 `.html`。
- HTML 應為可離線開啟的單一檔案，不依賴 CDN、遠端字型或建置伺服器。
- 同時支援桌面投影、鍵盤翻頁、手機垂直閱讀與瀏覽器列印。
- 主要內容應包含研究問題、方向性難題、處理策略、實際結果、證據邊界與下一步。
- 技術 bug、下載或環境問題只作為附錄紀錄，不取代研究方向的分析。
- 不得把預期、缺失或尚未執行的結果呈現為實際證據。

## 寫作方式

- 第一頁直接寫目前完成、尚未完成、正在使用的資料，以及這批資料要解決什麼問題。
- 使用研究生向老師報告進度的自然語氣，先說實際狀況，再補方法名稱與數字。
- 標題以具體問題或進度為主，避免口號、過度抽象的概念或為了整齊而硬湊的對仗句。
- 能用中文說清楚時不要堆疊英文術語；必須使用術語時，先用一句白話解釋用途。
- 每一頁只處理一個問題，明確區分「已完成」、「目前結果」與「還沒完成」。
- 研究方向的困難放在主頁；程式 bug、下載與建置問題只放技術附錄。
- 避免常見 AI 文風，例如過度使用「不是……而是……」、空泛強調重要性、重複總結或沒有具體內容的研究口號。

## 資料集說明

只要報告使用外部資料集，就必須有一頁明確列出：

- 資料集正式名稱、公開來源與論文或 DOI。
- 資料收集硬體，包括處理器、核心數、記憶體、儲存設備與相關平台配置。
- 可用的感測欄位、環境條件、控制方式與工作負載。
- 本研究實際使用的輸入特徵與預測目標。
- 資料與最終研究場景之間的差異，以及不能由這批資料支持的主張。

## 使用者指定關鍵詞

若使用者或指導老師曾指定多個研究關鍵詞，報告必須提供一頁逐項追蹤：

- 每個關鍵詞在研究中的角色。
- 目前狀態為進行中、已完成、未支持或尚未評估。
- 已完成的實驗與可報告結果。
- 尚未執行的原因和開始前必須具備的條件。

不得只展開目前進行中的一個詞，而省略其他已登錄方向。現有指定方向包括 `GRU`、`LSTM`、`PID` 與機箱／設備櫃；其中機箱方向正在進行，其他三項目前仍為尚未評估。

## 命名方式

使用 `research_progress_YYYY-MM-DD_zh.html`，例如：

```text
outputs/reports/research_progress_2026-08-24_zh.html
```

除非使用者明確要求，未來不需要另外產生 `.pptx`。研究主張或數值改變時，HTML 報告仍須遵守儲存庫的來源同步與證據規則。
