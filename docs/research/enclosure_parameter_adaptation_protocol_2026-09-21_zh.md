# 機箱參數調適示範 Protocol（2026-09-21）

**定位：本週完成的機箱主軸方法設計；尚未是實體機箱控制結果。**

## 1. 模型參數與控制輸入分層

以下描述的是「機箱熱模型如何表示控制與熱反應」，不是已取得的實體機箱設備規格。`PWM` 是模型的控制輸入，`RPM` 是模型的觀測回應；真正硬體介入仍需另外建立資料與 API。

| 參數 | 類型 | 能調什麼 | 會產生的效果 | 研究意義 |
|---|---|---|---|---|
| `PWM`（0–100%） | 操作參數 | 當下風扇命令 | 影響風量、CPU/GPU 降溫速度與風扇功耗 | 真正送給風扇的控制動作；必須和 RPM 分開記錄 |
| `RPM` | 回應／觀測量 | 通常不是直接調的；由 PWM、風扇曲線與負載決定 | 反映實際風扇轉速與致動延遲 | 檢查「命令有沒有真的變成風量」 |
| `Kp`, `Ki`, `Kd` | 控制器參數 | 溫度誤差轉成 PWM 的強度、累積與微分 | 反應快慢、overshoot、振盪與穩態誤差 | 比較 PID、前饋＋PID 等控制策略 |
| `C`（熱容量） | 模型辨識參數 | 機箱／元件儲熱能力 | 決定升溫、降溫的快慢 | 讓模型能預測暫態，而非只擬合當下溫度 |
| `G`（熱導／散熱係數） | 模型辨識參數 | 機箱向環境散熱的強度 | 決定無操作時回到入口溫度的速度 | 描述機箱結構、風道與環境交換 |
| `k_f`（風扇冷卻增益） | 模型辨識參數 | RPM／風量對散熱的影響 | 預測提高風扇後能降多少溫 | 是「操作 → 溫度結果」的核心係數 |
| `τ_f`（風扇／感測延遲） | 模型辨識參數 | 命令到溫度反應的時間位移 | 預測何時開始降溫、避免過早加大 PWM | 防止控制器追著尚未出現的反應亂調 |
| `k_L`（負載前饋係數） | 模型辨識參數 | CPU/GPU 功率或負載對發熱的影響 | 負載上升前先提高風扇，減少溫度尖峰 | 將工作負載變化與風扇控制分開 |
| `T_warn`, `T_limit` | 安全／固定參數 | 警告與硬性溫度上限 | 超過時強制提高風扇或回退安全策略 | 不能為了得到較好 MAE 事後修改 |
| `ΔPWM_max` | 安全／實驗參數 | 每一步最多改變多少 PWM | 限制抖動、噪音與機械衝擊 | 讓不同控制器在相同命令平滑條件下比較 |
| `H`（預測 horizon） | 實驗設計參數 | 預測 1、5、10 分鐘等距離 | 影響短期準確度與提前控制能力 | 必須預先固定，不能看結果後挑 horizon |

## 2. 具體調適順序

1. **先固定安全與實驗規則**：PWM 上下限、`T_limit`、`ΔPWM_max`、取樣時間與 `H`。
2. **用 calibration 負載階躍辨識 `C`、`G`、`k_f`、`τ_f`、`k_L`**；輸入至少要同步保存入口溫度、CPU/GPU 溫度、功率、PWM、RPM。
3. **鎖定熱模型後**，只在 calibration 搜尋 `Kp/Ki/Kd` 或前饋權重。
4. **在 validation／holdout** 只執行鎖定的控制器，不回頭調參。
5. 每個候選操作都記錄：預測溫度、實際溫度、MAE／RMSE、最大溫度、settling time、PWM／RPM、風扇功耗與是否 throttling。

## 3. 本週可展示的示範形式

對同一個機箱狀態，比較 `PWM=40%／60%／80%`：

```text
狀態：入口溫度、CPU/GPU 溫度、負載／功率、目前 RPM
模型：預測各 PWM 在 H 分鐘後的 CPU/GPU 溫度
選擇：不超過 T_limit 且功耗較低的候選
執行：送出選定 PWM
驗證：|實測溫度 − 預測溫度|，再累積 MAE／RMSE
```

BMC／bmcdata 目前可以支援觀測性預測與欄位／單位驗證，但沒有可重設的 PWM 介入，因此不能單獨支持因果控制結論。真正的機箱控制 gate 需要實體風扇或可重設的機箱 FMU／simulator。
