# 公開熱傳場景：我可以先做哪些模擬

查閱與功能檢查日期：2026-10-12。目標是先用外部提供的場景研究傳熱與控制，不等待實體機箱。下面分開列出「文件確認」「本機跑通」與「線上服務連線」，不將它們當作控制效果或硬體成果。

「網路上有公開模型」「在瀏覽器雲端求解」「遠端每一步送控制」是三件不同的事。HotSpot／TCLab 可下載在本機跑；SimScale 是雲端 CFD 場景；BOPTEST 的文件提供遠端時序 API。靜態資料集只有已發生的溫度／功率記錄，無法回答換一個 PWM 後會如何演化。

## 我如何選擇下一步

我把 **SimScale 電子盒**列為幾何／傳熱場景的優先候選，因為官方場景明確包含接觸與風扇，而不是只改一個散熱係數。可先用它核對熱路徑、溫度分布和代表性感測位置。要做 LQR，仍須確認瞬態模擬／資料輸出與介入方式，再建立局部狀態模型；不能直接拿穩態迭代曲線辨識熱容量。

我把 **HotSpot**列為不依賴雲端帳號的公開電子熱模型候選。先保留其原版功率、floorplan、材料和初始條件作來源對照。需要風扇控制時，還要設計可重設、可逐步操作的 adapter，以及 RPM／流量／對流參數的映射；本次尚未完成這些步驟。

我把 **TCLab**列為較快的控制流程練習平台。它能先回答「只有兩個感測點時，我如何估測內部狀態並產生受限控制」；它不能回答金屬片／風管實際散熱是否改善。既有2026-09-21 TCLab pilot不重跑；本次固定輸入介面檢查是另行登錄的 readiness 檢查，沒有演算法比較。

**BOPTEST**保留為不同場景的動態方法測試候選，不作機箱主場景。本次失敗只反映目前執行環境的 DNS 解析。先前本機 FMU 的研究證據仍維持原範圍，不將它轉成今日線上服務成功。

## 帳號、費用與可重現性

[SimScale 官方方案](https://www.simscale.com/product/pricing/)於查閱日列出免費 Community、有限次數的定量模擬和運算額度；超出免費次數後的結果存取有條件。這不保證特定教學的完整功能或這個帳號仍有額度，本次沒有建立帳號、購買或啟動雲端計算。官方教學的匯入／完成專案連結未能由文字讀取工具開啟，實際匯入狀態保留未確認。不能把線上公開專案直接等同可自由重散布 CAD；匯出／再利用前需核對平台和專案條款。

HotSpot 使用官方 LICENSE 的允許使用／修改／散布條款，需保留著作權及條款，不自行改稱 MIT。TCLab setup.py標示 Apache Software License；使用原版來源時保留該來源標示，不把文件可閱讀當成硬體資料授權。BOPTEST 的程式、模型與 weather 等資源可能具有不同授權，採用時需依固定版本逐項確認。

本次 pinned來源：

- HotSpot `f18831e48cef5d62580585cca0d7fab6c71bc3cc`；Apple clang21.0.0 ARM64、`make hotspot`，未啟用 SuperLU；官方 example1 輸入未改。

- [本次完整 readiness紀錄](../../openspec/changes/discover-public-thermal-scenes-20261012/artifacts/readiness.json)，含來源、輸入 hashes、介面狀態與錯誤。

HotSpot 範例環境溫度318.15 K＝45°C，已超過目前室內方法20–30°C的既有驗證範圍。範例只跑1秒暫態，因此跑通也不代表充分暖機。後續若評估我的模型，必須先定義新的溫度域、完整時間尺度、獨立資料切分、只給稀疏感測的資訊契約與共同校正預算，再凍結執行；不為了讓結果好看而修改已開啟的原版輸入。
