# SPB-001 Preregistered startup boundary protocol
Freeze all new source/config/protocol, prior2h bank result and calibration files, old PI/tuning code and officialFMUs before any new simulation. Existing five known devices:air,hydronic,heat_pump,apartment,commercial. Use only their accepted2h models from model-consistent-compensation;6h is outside this explicitly2h study, not discarded by outcomes. Fixed q=.5, same normalized actuator bounds and auxiliary installation controls as MCC-001.

Startup challenge:24h warmup using21C thermostat targets (declared target override inputs only); at t0 target becomes22C, keep measured actual temperature/state rather than force21C, and primary actuator handover preserves readback. Apartment's fixed-open day valve may prevent21C room temperature; report actual initial temperature. Do not compare these trajectories as paired with prior22C-warmup rounds.

Baseline: original PI equations, initial integral chosen for bumpless actual actuator handover. Candidate: same PI plus startup desired correction clip(kp*error,±.1u), correction slew≤.02u per60s. Baseline has no correction. Candidate only starts if initial|error|>band. Bands .05,.1,.2C. Exit irrevocably after5 consecutive samples inside band, first crossing of initial error sign, or elapsed60min, whichever first; initially inside band skips assistance. On exit add current correction to integral then set correction0, so unsaturated PI command before/after transfer is identical at the current observation. Conditional integration uses combined command during assistance, ordinary PI after exit. No observer, environmental inverse or recurrent rearming. All constants shared, no plant-name branch. Bumpless command algebra does not imply unchanged late trajectory.

Fixed windows:early first60min;late from minute60 to end, same windows for every policy regardless exit. Record MAE,RMSE,maxabs,TV,saturation,energy; acquisition time first start of15 consecutive one-minute post-step temperatures within±.1C and confirmation time; absent acquisition is null/right-censored, never0. Domain violations and actual initial error retained.

Development selection:day8,3h each, baseline plus three candidates =4 episodes/device,20 total. Per-device candidate eligible if early MAE improves by at least max(.001C,1% baseline earlyMAE), earlymax≤baseline+max(.02C,5% baselineearlymax), lateMAE≤baseline+max(.002C,5% baselinelateMAE), latemax≤baseline+max(.02C,5% baselinelatemax), lateTV≤1.10*baselineLateTV+.02. If baseline acquisition exists, candidate acquisition must exist and be no later than baseline+1min. Select eligible smallest earlyMAE, ties prefer larger exitband. If none eligible choose purePI. Save all device selections/snapshots before any confirmation. This is the same automatic limited-trial procedure per device, not manually selecting for each evaluation result.

Confirmation:days35/70,24h, baseline and selected policy. If purePI selected, reuse each baseline trajectory with explicit reference rather than simulate or count an identical second episode. Baseline always executed; nonfallback candidates each run once per date. No opened-date retuning. Same per-date early/late gates; fallback equality is preservation, not improvement. Describe conditional pipeline confirmation on development plants, not unseen-plant generality.

Cost:zero new calibration, existing2h data/device; development4x3h=12h/device trials, total nominal adaptation14h including identification. Baseline needs no such search for deployment; do not hide the extra12h or claim lower total tuning cost. Development20x(24+3)=540 aggregate simulatedh; confirmation10 to20 unique episodes x48h=480..960h. Total30..40 unique FMU episodes/1020..1500h. Track shared reference traces, wall time, early/tail errors and failed criteria for every band. Do not average operative/air absolute MAE into a pooled score.
